I. ft_strlen

평가자 질문 1
xor rax, rax는 왜 사용했나요? mov rax, 0과 어떤 관계가 있나요?

"""
둘 다 하는 일은 같아요. 단지 rax 를 0으로 만든다는 의미입니다.
xor rax, rax 같은 레지스터끼리 XOR 하면 비트 전부가 0이 됩니다. mov rax, 0 이랑 결과가 같습니다.

xor 을 사용한 이유는 다음과 같아요
1. 길이를 세기 전에 카운터를 0부터 시작해야 해요.
2. xor rax, rax는 기계어가 짧고, CPU도 이 패턴을 잘 알아봐서 보통 mov rax, 0보다 선호합니다.
3. xor 을 사용한 의미는 단순 "0을 넣는다" 이지, 비교나 문자열 조작하는것은 아닙니다.

※ xor rax, rax는 결과를 0으로 만들면서 CPU의 상태 플래그도 변경해. 반면 mov rax, 0은 플래그를 변경하지 않아.
다만 현재 코드에서는 바로 다음 반복문에서 cmp가 플래그를 설정하기 때문에 이 차이가 문제되지 않아.
"""


평가자 질문 2
rdi와 rax는 각각 무엇을 의미하나요?

"""
System V AMD64 ABI 기준으로 보면:

rdi: 첫 번째 인자. 여기선 const char *s, 즉 문자열의 시작 주소.
rax: 반환값 레지스터이기도 하고, 이 코드에선 지금까지 센 문자 수(인덱스) 이기도 합니다.
동작은 이렇습니다.

cmp byte [rdi + rax], 0
rdi + rax = 시작 주소 + 현재 인덱스. 그 바이트가 '\0'인지 봅니다.

inc rax
널이 아니면 인덱스를 1 올리고 다시 루프.

끝나면 rax에 길이가 남아 있고, ret하면 그게 size_t 반환값이 됩니다. 별도 mov로 반환값을 옮길 필요가 없습니다.

※ 정확해. 특히 이 설명이 좋았어.
rax는 반환값 레지스터이기도 하고, 지금까지 센 문자 수이기도 합니다.

rax를 카운터로 사용하면서 마지막에 별도 이동 없이 반환하는 구조를 이해하고 있다는 의미야.
"""

평가자 질문 3
cmp byte [rdi + rax], 0에서 문자열이 빈 문자열("")이라면 함수는 어떤 값을 반환하나요?

"""
"는 첫 바이트가 바로 0입니다.

xor rax, rax → rax = 0
cmp byte [rdi + 0], 0 → 바로 같음
je .done → 루프 한 번도 안 돌고 나감
ret → rax는 그대로 0
그래서 0을 반환합니다. libc strlen("")이랑 같습니다.

한 글자 "a"면 rdi+0이 'a'라서 inc 한 번 하고, 다음이 '\0'이라 1을 반환합니다.

※ ""와 "a"의 실행 흐름을 각각 추적한 것도 좋았어. 문자열 종료 문자인 '\0'은 길이에 포함되지 않는다는 점까지 설명하면 더욱 완벽해.
"""

II. ft_strcpy

Q1. 왜 시작에서 mov rax, rdi를 하나요?

"""
strcpy의 반환값은 복사한 문자 수가 아니라 원래 destination 포인터입니다.

char *strcpy(char *dst, const char *src);
ABI에서 반환값은 rax입니다. 그래서 함수 맨 앞에서:

mov rax, rdi
rdi에 들어온 dst 시작 주소를 rax에 저장해 둡니다.

루프가 끝나면 rdi는 이미 문자열 끝으로 가 있습니다. 그때 다시 dst를 구할 수 없으니, 복사 시작 전에 원본 주소를 백업하는 겁니다. 마지막 ret은 그냥 rax를 돌려줍니다.

※ 정확해. strcpy는 복사한 문자 수가 아니라 원래 dst 포인터를 반환하고, System V AMD64 ABI에서 포인터 반환값은 rax에 들어가.
한 가지 표현만 더 정확하게 하자면, 원본 주소를 복구할 수 없어서 저장한다기보다는, 반복문에서 rdi를 변경해도 원래 반환해야 할 주소를 유지하기 위해 미리 저장한다고 설명하면 좋아.
"""

Q2. 왜 rdx 전체가 아니라 dl인가요? dl은 몇 비트인가요?

"""
문자열은 1바이트씩 복사합니다. rdx는 64비트라서 mov rdx, [rsi]를 하면 8바이트를 읽습니다. "abc"처럼 짧은 문자열이면 널 뒤를 침범할 수 있습니다.

그래서:

mov dl, byte [rsi]
mov byte [rdi], dl
dl은 rdx의 하위 8비트 레지스터입니다. 8비트 = 1바이트.
byte를 명시한 것도 1바이트 접근이라는 뜻입니다.
레지스터 관계는 이렇습니다.

이름	크기
rdx
64비트
edx
하위 32비트
dx
하위 16비트
dl
하위 8비트

한 글자(char)를 옮기니까 dl이 맞습니다.

※ 정확해.
dl은 rdx의 하위 8비트이고, 문자열을 1바이트씩 복사하는 현재 구현에 적합해.
참고로 mov rdx, [rsi]처럼 8바이트를 읽는 코드는 문자열 종료 지점을 넘어선 메모리까지 접근할 수 있어. 경우에 따라 접근 가능한 메모리 범위를 넘어 문제가 발생할 수 있지.
"""

Q3. test dl, dl / jnz .loop는 무엇이고, "abc"는 몇 바이트 복사하나요?

"""
test dl, dl
jnz .loop
방금 복사한 바이트가 널 종료 문자인지 검사합니다.

test dl, dl = dl AND dl. 결과가 0이면 ZF=1.
dl이 '\0'이면 ZF=1 → jnz가 점프 안 함 → 루프 종료.
dl이 'a' 같은 일반 문자면 ZF=0 → .loop로 다시 감.
중요한 점: 먼저 복사하고, 그다음에 검사합니다. 그래서 널도 destination에 들어갑니다.

"abc" 실제 복사:

회차	복사한 바이트	그 후
1
'a'
널 아님 → 계속
2
'b'
계속
3
'c'
계속
4
'\0'
test에서 0 → 종료
4바이트를 복사합니다. 'a', 'b', 'c', 그리고 널 종료.
dst 결과는 "abc"이고, C 문자열로 끝나 있습니다. 3바이트만 복사하면 널이 없어서 strlen(dst)가 깨집니다.

빈 문자열 ""도 1바이트('\0')를 복사하고 바로 끝납니다.

※ 이 부분은 아주 정확해.
특히 다음 설명이 중요했어.
먼저 복사하고, 그다음 검사하기 때문에 '\0'도 destination에 복사된다.
mov dl, byte [rsi]
mov byte [rdi], dl
inc rsi
inc rdi
test dl, dl
jnz .loop


"abc"를 복사하면 총 4바이트가 복사된다는 설명도 맞아.
"""

Q4. rdi가 계속 증가하는데, 왜 원래 dst가 반환되나요?

"""
루프에서 inc rdi 하니까 rdi는 더 이상 시작 주소가 아닙니다. "abc"가 끝나면 rdi는 dst + 4를 가리킵니다.

그래도 원래 주소가 나오는 이유는 Q1에서 이미 rax에 저장해 뒀기 때문입니다.

시작:  rdi = dst 시작,  rax = dst 시작
루프:  rdi는 앞으로 이동, rax는 그대로
ret:   반환값은 rax → 원래 dst
rdi는 “지금 어디에 쓰나”용 포인터이고, rax는 “무엇을 돌려주나”용 백업입니다. 두 역할이 분리되어 있어서 rdi가 바뀌어도 반환값은 안 바뀝니다.

rsi도 같이 증가하지만, src는 반환하지 않으니까 저장할 필요가 없습니다.

※ 정확해.
rdi는 destination의 현재 쓰기 위치를 추적하고, rax는 최초 destination 주소를 보존한다는 식으로 설명하면 충분해.
이번 구현에서는 반복문이 rax를 변경하지 않으므로 마지막 ret 시 올바른 반환값이 남아 있어.
"""
